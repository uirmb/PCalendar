# PCalendar

**在线主页：** [打开 PCalendar](https://uirmb.github.io/PCalendar/)（首次使用需在仓库 Settings → Pages 中选择 main /docs 并保存）。

**PCalendar 是由寿星万年历（寿星天文历 V5.09）改造而来的现代日历与天文计算项目，仓库初始导入版本为 v1.4.0。** 原作作者为许剑伟；本项目保留原历法、天文算法与数据来源，在此基础上进行 TypeScript 模块化、界面现代化、多语言与多国家/地区日历扩展。

## v1.4.0 概览

- 九种界面语言：简体中文、繁体中文、英语、巴西葡萄牙语、日语、韩语、西班牙语、法语、德语。语言与日历地区独立选择。
- 首批 17 个国家/地区：中国大陆、香港、台湾、新加坡、美国、加拿大、英国、澳大利亚、新西兰、日本、韩国、巴西、德国、法国、西班牙、意大利、印度。
- 中国传统历法、国际公历月历/年历、公共假日、季节/月相，以及纽约公校和 ASP 停车日历。
- 纯前端运行，支持静态部署和离线单文件。专业页面部分历史说明和长文本仍保留中文。
- 国际公共假日重点覆盖 2026 年；地方资料标明适用范围及覆盖年份。

## 项目沿革与使用说明

以本次提供的 **寿星天文历 V5.09** 为基准，用 **TypeScript + Vite + HeroUI 官方样式包**重写界面与程序结构。原作作者为**许剑伟**。

**当前版本为 1.4.0。** 项目保留原历法和天文计算内核，用所选国家、城市和时区组合当地日历。中国模式显示完整农历、节气和中国节日；美国模式提供公历年历、美国节日、四季与月相，纽约市另有可选公校和停车日历。它是纯前端项目，所有计算都在浏览器中完成，年度资料随离线构建提供。

## 直接使用

压缩包已经包含生产构建，不需要先安装开发环境。

### 方式一：直接双击离线版

打开：

```text
dist/sxwnl-modern.html
```

脚本、HeroUI 样式、图标、地图数据和帮助插图都已经内联。使用现代浏览器直接打开这个文件即可；不依赖 CDN、地图 API 或后端服务。它由同一次 Vite 构建自动生成，和常规部署版使用同一套应用代码。

### 方式二：部署到静态服务器

将 `dist/` 目录内的文件整体部署到 Nginx、lighttpd、IIS 或其他静态网站服务器，访问 `index.html`。项目使用相对资源路径，支持部署在子目录内。

`dist/index.html` 是标准 Vite 入口，使用 HTTP/HTTPS 访问；本地双击使用上面的 `sxwnl-modern.html`。

## 界面操作

- 点击日期固定右侧详情；桌面悬停显示摘要，按住 Ctrl 可以暂留预览。
- 日期网格支持方向键、Page Up/Page Down、Shift + Page Up/Page Down、Home/End。
- “跳转日期”支持 `B212`、`b212`、`*212`、`-211` 等原版公元前输入约定。
- 1582 年 10 月遵循原版改历：4 日之后为 15 日，不补造不存在的日期。
- 右上角“地区与日历”是统一入口。依次选择大洲、国家和城市，日历内容、当前时钟、观测坐标和时区会同步更新。
- 选择美国时默认使用纽约市作为东部时区参考地点；需要其他地点时可更换城市。中国模式保留原省市和全部地点选择。
- 国家与明确的行政城市决定节日和当地事项，时区决定当地日期及事件时刻，观测坐标决定日月升降等地方天文结果。高级设置支持自定义观测点和固定 UTC 偏移。
- 中国模式显示农历、二十四节气、干支、生肖及中国纪年；美国和其他地区的日期格、详情、悬浮摘要、复制文本均移出这些内容。中国专属专业入口随地区显示，切回中国后恢复。
- 美国模式显示联邦节日、单独的补休日、可选文化和商业日期；纽约市有独立的公共事务、公校、ASP 日历。其他国家本轮显示通用公历、月相和天文信息，明确提示节日资料尚未配置。
- 时区使用 IANA 地区标识，由浏览器 Intl 按目标日期应用时区历史和夏令时规则；TD/JDE 等专业时标继续明确保留。
- “今天”模式会随所选时区跨日；手动查看历史日期时，时钟继续走，所选日期保持。点击“今天”可恢复跟随。
- 地点与时区更改会重算相关内容，并保留已手动填写的专业日期和当前计算模式。仅改变主题、周起始或时钟格式不会重置专业计算。
- 每周起始和时钟的 12/24 小时制可跟随地区，也可以手动指定。界面语言本轮保持简体中文，选择美国不会强制改变语言。
- 地点、时区与显示偏好保存在当前浏览器。存储被浏览器限制时，当前会话仍可使用。
- 专业工具在计算期间禁用本次按钮，防止重复启动；切换页面会暂停日月实时坐标刷新。
- 手机端使用顶部菜单打开完整导航，表格和长报告在自身区域内滚动。

## 地区日历与时间模型

### 中国与美国

月历以公历日期为基础，按国家和明确的地方身份组合显示内容。中国模式继续保留原农历排月、闰月、干支、古代历法订正与节气。美国模式使用当地日期、可选十二星座、节日与生活事项、四季及月相，顶部卡片显示接下来的已启用事项。通用星历、日月食、月相、日月升降和计算工具继续可用；中国农历年历、八字和定气定候入口仅在中国模式显示。

美国节日区分节日本日、联邦补休日、文化纪念日和各地方层。联邦规则覆盖 1971 年起，按已接入的历史生效范围计算；未来年份按现有规则推算。周末补休日针对常规周一至周五联邦员工，不代表所有人的休息日。纽约地方资料按各自年度公告覆盖，其他地方日历尚未收录。中国官方休班收录 2026 年安排，其他年份会明确显示官方调休未覆盖。具体来源、各项生效范围及限制见 [docs/HOLIDAY_DATA.md](./docs/HOLIDAY_DATA.md)。

本轮先验证中国、美国。其他国家和地区提供当地日期、时区、月相和观测能力；没有地区节日包时明确显示“节日资料暂未配置”，不会借用中国或美国节日。

### 全天节日与天文时刻

圣诞节这样的全天事件按当地公历日期保存，例如美国圣诞节始终属于当地 12 月 25 日。它不使用“北京时间零点再转当地时间”的方式。

月相、节气等精确天文事件以同一 UT 瞬间转换成当地日期和时间。跨日跨月时，事件列表、日格标记和详情同步调整；中国农历排月本身仍按原历法计算。以当地时间填写的观测输入按所选时区换算，标为 TD/JDE 的输入和输出继续表示原时标。

### 时区与观测地点

时区使用 `America/New_York` 等 IANA 标识。UTC 偏移在每个目标瞬间计算，自动处理夏令时，支持离线运行；具体时区规则版本由运行浏览器或操作系统的 Intl 数据决定。固定偏移模式不自动切换夏令时。

海外城市采用 IANA tzdb 2025b 的 zone.tab 参考地点；各代表城市都有自己的坐标。目录保留中国原版 3,192 条地点，美国提供 29 个时区参考城市。选择城市会同时更新地点名称、经纬度和时区。高级自定义模式允许指定其他观测点，界面会清楚标明日历地区与自定义坐标的作用。城市目录的资料版本与浏览器的时区规则版本分别记录，二者不混为一项。

古代天文日期和混合历法仍保留原算法。IANA 的历史偏移（包含地方平太阳时）可能与旧版全年固定偏移不同，因此本轮保留原天文数值的严格对照，并独立验证新时区显示；不会把旧时区资料当成现代全球规则。浏览器时区历史不应被理解为对古代所有地区民用时间的史料证明。

### 旧设置迁移

升级后继续读取已有设置。旧版明确选择“美国东部”而观测位置仍为默认天安门时，会转为美国日历及纽约市参考点；可识别的自定义坐标继续作为自定义观测点保留。

仅有固定 UTC 偏移时，不通过偏移猜国家。能确定为原中国地点的设置保留中国地区；无法确定地区的自定义观测点保留坐标与偏移，并以“未指定国家/地区”提示用户选择日历地区。旧显示偏好继续保留，已保存的计算偏移不会被旧独立世界时钟偏好擅自覆盖。

## 技术说明

依赖版本锁定为：

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| TypeScript | 7.0.2 | 应用、算法、控制器与构建辅助脚本 |
| Vite | 8.3.3 | 开发服务与生产构建 |
| @heroui/styles | 3.2.6 | 官方视觉样式与设计令牌 |
| tsx | 4.23.15 | 执行 TypeScript 测试和单文件构建脚本 |

本项目使用原生 TypeScript 和标准 DOM/Canvas，通过 `@heroui/styles` 实现 HeroUI 风格，不引入 React 运行时。HeroUI 官方提供这一框架无关的样式使用方式：[Frameworks / Other Frameworks](https://heroui.com/en/docs/react/getting-started/frameworks)。本版样式包已包含预编译 CSS，但包的 `exports` 未列出该文件，因此 `vite.config.ts` 用显式别名定位其预编译文件。

应用逻辑不依赖全局元素 ID 变量、`document.all`、内联事件、动态执行脚本或 iframe。TypeScript 开启 `strict`，没有用 `any`、`@ts-nocheck` 或 `@ts-ignore` 绕过应用代码检查。

计算内核保留原公式、运算顺序和数表。原有跨脚本依赖收拢为 ES 模块，公开类型和新版界面调用位于独立 facade。保留较大的核心模块是为了让数表和算法与原版逐段可核对。

原代码对 `Number.prototype.toFixed` 的覆盖已替换为局部 `legacyFixed()`，专业结果保留旧版舍入行为，不修改浏览器原生对象。原始 JavaScript 仅放在测试基准或原始包备份中，不参与新版页面运行。

### 独立复用历法计算

```ts
import {
  getMonthCalendar,
  getSolarTerms,
  getSunMoon,
} from './src/engine';

const october = getMonthCalendar(2026, 10);
const day = october.days.find((item) => item.d === 6)!;
const solarTerms = getSolarTerms(2026);
```
