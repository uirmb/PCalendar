# 寿星天文历现代化：功能对照与回归边界

当前版本为 **1.3.0**。原历法与天文计算的迁移对照、按地区调整的界面，以及新增纽约生活日历分别说明；历史版本的通过记录保留，不作为当前浏览器界面已完成验证的推断。

## 对照基准

原历法与天文功能以本次上传的 `sxwnl.zip` 为唯一迁移基准：主界面显示 **V5.09**，作者为许剑伟；`indexmp.htm` 注明 2018 年做了适应手机的改动。不是依据另一个在线版本或后来社区分支推测功能。1.2、1.3 经确认新增的地区时区、节日与地方安排使用独立数据层，不把这些新资料伪称为原包内容。

已逐项检查 `index.htm`、`indexmp.htm` 的表单、链接、按钮、内嵌函数，以及 `tools.js`、`eph0.js`、`ephB.js`、`eph.js`、`JW.js`、`lunar.js`、`page_gj.js`、`vml.js`、`help.js`、九章帮助及独立 `界线图.htm`。原作署名及使用说明见 [ORIGINAL_NOTICE.md](./ORIGINAL_NOTICE.md)。

`index.htm` 与 `indexmp.htm` 的功能集合相同。两者的区别是表格宽度、月历详情位置、换行、边框、诊断区位置和日食搜索结果每行数量（10 条与 4 条）。它们加载相同的外部计算模块，内嵌计算函数也相同；现代版使用一个响应式界面覆盖桌面和手机布局。

### 天文瞬间与显示偏好

美国月历与公历年历增加春、夏、秋、冬开始时刻，沿用原太阳视黄经反解，取 0°、90°、180°、270° 四个季度点。季节名称按北半球解释，说明中提示南半球季节相反。月相继续使用原引擎时刻；这些事件按各自 UT 对应的地区偏移转换日期，可跨日、跨月，不能像全天节日一样固定为一个民用日期。

地区模式按真实 IANA 偏移变化查找时钟调整，列出切换前后钟表时刻、偏移和拨快/拨慢的长度；只有地区名称明确标识 Daylight / Summer 时称夏令时，其余称时区偏移调整。固定 UTC 偏移模式不产生夏令时切换事件。未来日期仍依赖浏览器所带规则，不是未来行政变更的保证。

日期格式可选跟随地区、年.月.日、月/日/年、日/月/年；美国自动采用月/日/年，其他地区自动采用年.月.日。时钟保留跟随地区、12 小时或 24 小时选项，每周首日可跟随地区或手选。时刻格式作用于月历、出没、复制与公历年历等显示，日照和白天时长保持持续时间含义。国际模式可关闭十二星座显示；该开关不删除 CN 原星座字段。JD 等天文详情可展开查看。

主题、日期格式、时钟、周起始、十二星座与各日历层分别持久化。显示偏好不重置专业计算输入；国家、地点或时区改变时只更新相关计算依赖，手动日期和编辑过的地方食名单保留。第八页分别记忆 CN 气朔、US 季节/月相和其他地区月相的上次动作。公历年历与原农历年历分别提供入口行为，不用公历缩略图替代原排月报告。

## 1.2 地区日历与现代时区（历史记录）

## 1.1 统一地点与时间的行为调整（历史记录）

按照新增交互要求，原来的独立世界时钟和地点设置合并为一个“地点与时间”面板。默认天安门对应中国 UTC+8，不取浏览器宿主时区；用户可选择原库地区规则或手动固定偏移。地区选择只决定时间规则，天文观测仍使用面板中的经纬度。旧版保存的有效计算偏移按固定模式保留，旧世界时钟选择不会自动覆盖原计算偏移。

“今天”表示跟随所选时区的当前日期，修改时区或午夜跨日会同步日期。手动选择的历史日期保持不变，再点击“今天”恢复跟随。专业页保留用户手动日期、参数和最后一次计算动作；地点或时区变化只刷新相关输出，主题与周起始设置不会重新生成专业结果。

时区显示转换对**同一个已确定的天象瞬间**保留其 UT / TD，只改变当地日期与时间；如果输入框选择“输入为当地时间”，在时区改变后，相同墙上时间会重新换算为新地区的 UT / TD。这个区别适用于日月食、行星和恒星等输入。农历年月日、历史订正与月份归属继续依原中国历法，精确天象显示可以位于相邻当地日期。

地区模式按每次事件对应的 UT 查询原夏令时规则，包括南半球跨年区间。切换日的不同日月升降事件可能采用不同偏移，因此摘要标明地区当地时间；持续时长保留原差值。当地时间重复时采用较早的 UT，缺失时段按跳时长度向后顺延。这一段描述 1.1 的原库规则；1.2 起已改为离线 IANA。

## 日期、天文与历史边界

1. **天文纪年含 0 年。** 输入 `B212`、`b212`、`*212` 与 `-211` 表达相同年份；`B1` 对应天文 0 年。界面必须清楚显示规则。原月历标示的计算范围为公元前 4713 年至公元 9999 年；“计算得出”不等于该范围内所有日子均与历史实际历书一致。
2. **原作者把与实历相符的起点标为公元前 722 年。** 更早历法保留推算，不当作逐年史料认证。王莽、魏景初、武周、唐肃宗等改月名段不能用现代农历库替代；测试必须包含 8–23、237–239、689–701、761–762 年，以及春秋、秦汉边界。
3. **1582 年改历保持原版混合规则。** 1582-10-04 后为 1582-10-15，10 月只有 21 个实际历日。不能生成通常的 1–31 连续日期后对索引错位。
4. **2033–2034 置闰必须跟随原气朔排月。** 用这些月份对照原 `SSQ`、月名、闰标记与精确时刻；不采用表面上“一个无中气月即闰月”的简化规则。
5. **时间基准不同。** 底层农历气朔数据使用北京时间，1.1 的月历、年历与气朔专业页将精确时刻转换为所选地区显示；专业星历和食计算的输入采用所选地方时或 TD，固定时区设为 0 时地方时即 UTC。功能映射表中的 `UTC/TD` 是原页面标签，原实现实际也使用所选时区换算。原 `curTZ` / `SZJ` 接口使用 `-8` 表示东八区，现代界面显示 `UTC+08:00`，转换方向保持一致。
6. **历史 ΔT 与星历数据保留。** 沿用原 ΔT 估计、行星级数、月球模型和 NASA 月径选项；现代化界面不等于重新标定观测精度。1.2、1.3 单独更新地区时区、CN/US 节日和纽约生活日历显示层；官方安排只在明确列出的覆盖范围内提供，传统纪念日、公校安排和停车提醒不自动代表全民休假。
7. **原型与脚本全局改为模块。** 原代码会覆盖 `Number.prototype.toFixed`；现代应用使用局部同算法格式化，以保持报告结果并避免修改整个浏览器的内建原型。独立 oracle 在 Node `vm` 内运行原脚本，不能污染测试进程。
8. **比对的意义。** 新旧数值一致证明迁移保留了原算法行为；不证明原算法绝对无误，也不是与当代权威星历做独立精度认证。图形外观、响应式布局和可访问性需要另外在浏览器验证。

## 回归设计

原始基准仅放在 `tests/fixtures/original/`，有 SHA-256 清单，不参与生产页面。测试使用独立 `vm` 上下文逐文件按原顺序执行；现代端直接导入 TypeScript 导出的引擎。对相同输入比较原始数值、中文字符串、精确时刻和相关对象字段，不把现代输出反过来写成“正确答案”。
