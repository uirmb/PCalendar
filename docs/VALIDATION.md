## 复现方式

安装项目依赖后运行：

```bash
npm install
npm test
npm run typecheck
npm run build
```

测试只使用本地文件，不请求在线星历服务。所有测试基准位于 `tests/fixtures/original/`，有字节数及 SHA-256 清单。若误改基准文件，测试会失败。

如果当前环境对 `tsx` 命令的临时 IPC 管道有限制，可以直接执行 `node --import tsx --test tests/*.test.ts`；此方式同样执行所有 TypeScript 测试。浏览器生产构建不需要这些原 JavaScript fixture。

浏览器测试是可选的独立验证，不会被 `npm test` 隐式启动。安装 Playwright 与 Chromium 后运行：

```bash
npm install --no-save playwright
npx playwright install chromium
npm run build
# 当前 1.3 国际地区、纽约日历与专业页联动
node tests/browser.international.mjs
node tests/browser.nyc.mjs

# 直接打开单文件并关闭网络
node tests/browser.offline.mjs

# 可选：完整传统 CN 界面/图形回归与原 1.1 联动场景
node tests/browser.smoke.mjs
node tests/browser.time-settings.mjs
```

已提供浏览器的受限环境可以设置 `CHROMIUM_EXECUTABLE`。若 Playwright 安装在项目之外，设置 `PLAYWRIGHT_MODULE` 为其绝对模块路径；`CHROMIUM_ARGS_MODULE` 可指向导出 `args` 的 serverless Chromium 模块。HTTP 脚本的 `SMOKE_DIST` 和 `SMOKE_REPORT` 分别指定构建目录与报告路径；`SMOKE_FILTER` 可用测试名称正则表达式执行定向回归。HTTP 脚本创建临时端口并在完成后关闭服务，无须预先启动 Vite。离线脚本使用 `OFFLINE_HTML`、`OFFLINE_REPORT` 指定单文件和报告，不启动服务器。旧 smoke 和 time-settings 脚本用于传统 CN 及原统一设置场景，默认分别写入 `browser-smoke-current.json` 和 `browser-time-settings-current.json`，避免覆盖交付中保留的历史报告。本轮实际执行的是国际 12 组、纽约 13 组和单文件 8 组；两个旧脚本的全量当前运行不列为通过。
